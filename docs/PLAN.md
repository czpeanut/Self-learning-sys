# 自習練功房：系統規劃

> 國中生自主學習系統，部署於**無人化智慧 K書中心**（館內**沒有**輔導老師）：學生到館簽到後自習，系統依錯題自適應出題、記錄專注時間，卡住時由 **AI（Gemini）解題講解**，並把學習狀況回報給家長。
> AI 解題沿用 student-app 的解題模組（同一套提示詞、`gemini-3.7-flash`、幾何輔助圖 `GeometryFigure`）。
> 學生自己選練習範圍，系統出一波題目，**依錯題狀況產生下一波**，結束後產出**學習狀況評估報告**。
> 知識點目錄沿用 [student-app](https://github.com/czpeanut/student-app) 的 `lib/taxonomy.ts`（9 科：科目 → 大單元 → 知識點）。

---

## 1. 核心流程

```
選範圍（科目 / 大單元 / 知識點）＋ 設定（每波題數、波數、難度、計時、過關門檻、目標）
   │
   ▼
第 1 波：程度檢測 ── 每個知識點平均分配題目，難度依歷史掌握度決定
   │
   ▼
逐題作答 ── 選答案 → 依「把握度」送出（有把握／不太確定／用猜的）→ 立即看對錯與詳解
   │         可看提示（會降低加分）、可跳過
   ▼
本波結果 ── 各知識點答對數＋掌握度、錯題錯因標記（自動判斷，可更正）
   │         顯示「下一波計畫」及理由（例：上一波錯 2 題，加強並出變化題）
   ▼
引擎規劃下一波 ── 已過關的知識點移出；錯得多、掌握度低、觀念錯誤的加重；
   │               錯題改出「變化題」（同觀念換數字／情境）；難度依表現升降
   ▼
（重複，直到全部過關／達到波數上限／學生自行結束）
   │
   ▼
學習報告 ── 正確率、各波趨勢、知識點前後掌握度、錯誤類型、自我認知、評語與下一步建議
           錯題自動進錯題本，依 1/2/4/7/15 天間隔排入複習
```

## 3. 自適應引擎設計（`lib/engine.ts`）

### 3.1 掌握度（每個知識點 0–100）
- 題目難度對應門檻分：基礎 35／標準 60／進階 85
- 預期答對率 `p = 1 / (1 + e^(-(掌握度 - 門檻) / 12))`
- 答對：`+K × (1 - p)`，並乘上折扣：不太確定 ×0.7、用猜的 ×0.3、看過提示 ×0.5
- 答錯：`-K × p`；**有把握卻答錯 ×1.2**（觀念錯誤比不會更需要處理）
- K：前 5 次 24（快速定位程度），之後 16
- 等級：<55 待加強、55–79 進步中、≥80 已掌握

### 3.2 錯誤類型（自動判斷，學生可改）
| 類型 | 判斷條件 | 報告給的建議 |
|---|---|---|
| 猜題 | 自己標「用猜的」或跳過 | 先看提示再作答 |
| 粗心失誤 | 有把握，且作答時間 < 建議時間的 25% | 交卷前檢查符號、單位 |
| 觀念錯誤 | 有把握卻答錯 | 重讀定義與詳解 |
| 不熟練 | 不太確定且答錯 | 多做基礎題 |

### 3.3 下一波規劃
1. **過關判定**：本次至少作答 2 題、最近 2 題連對、掌握度 ≥ 門檻 → 移出範圍
2. **優先度** = `(100 - 掌握度) + 30 × 上波錯題數 + 20 × (尚未練過) + 15 × 觀念錯誤數`
3. **題數分配**：依優先度用 D'Hondt 法分配本波題數；單一知識點上限 `max(3, 題數/知識點數)`；剩下的知識點少時縮小這一波的題數
4. **難度**：依掌握度（<45 基礎、<75 標準、其他進階），上波全錯降一級、全對升一級
5. **變化題**：上一波答錯的題，要求 AI 出同觀念、不同數字／情境的題目
6. **結束**：全部過關 → `all-passed`；達到波數上限 → `max-rounds`；學生按結束 → `user-ended`

`npm test` 會跑模擬學生：3 個知識點的真實能力分別是 90／60／25，驗證強項很快過關、後續出題集中在弱項，且掌握度會往真實能力收斂。

## 4. 架構

```
Next.js 14 App Router + TypeScript + Tailwind（與 student-app 相同技術棧，方便日後整合）

app/
  page.tsx                 首頁
  practice/new             範圍選擇＋設定
  practice/session?id=     作答（每題、每波回顧、下一波）
  report?id=               學習報告
  wrong-book               錯題本

  study                    K書模式：簽到、番茄鐘、今日目標、今天問 AI、簽退心得
  parent?date=             家長日報／週報／留言給孩子
  api/generate             出題（產生器 → Gemini → 示範題）
  api/solve                AI 詳解（student-app 同款）＋「還是不懂」追問
  api/report               AI 學習教練評語
  api/status               是否有設定 AI
lib/
  taxonomy.ts              知識點目錄（student-app 快照）
  types.ts                 資料型別
  engine.ts                自適應引擎（純函式）
  generators.ts            數學離線出題器
  question-gen.ts          出題服務（server）
  gemini.ts                Gemini 呼叫核心（student-app 快照：重試、退避、逾時、thinking 上限）
  solve.ts                 解題提示詞／答案擷取／科目限制（由 student-app /api/solve 程式擷取）
  tutor.ts                 「還是不懂」追問提示詞、答案字母比對
  ai.ts                    出題與評語用的 JSON 生成（底層走 gemini.ts）
  report.ts                報告統計＋規則式評語（純函式）
  daily-report.ts          家長日報／週報／LINE 文字（純函式）
  storage.ts               本機儲存層（之後替換成 Supabase）
  session-client.ts        前端流程控制
components/
  SolutionView.tsx         詳解渲染（student-app 快照）
  GeometryFigure.tsx       幾何輔助圖 SVG（student-app 快照，防碰撞標籤）
  MathText.tsx             KaTeX＋表格（student-app 快照）
  AskAI.tsx                問 AI 介面（詳解、看懂了／還是不懂、追問）
```

**設計原則**
- 引擎、報告都是**純函式**，前後端共用、可單元測試；之後搬到 server 端做防作弊也不用改邏輯
- 儲存層集中在 `lib/storage.ts`，換成 Supabase 時只改這個檔案
- 出題有三層備援：程式產生器 → AI → 示範題，AI 塞車時練習不會中斷
- 報告的 AI 評語只送統計摘要（不送題目全文），省 token

## 5. 第二階段規劃

1. **帳號整合**：共用 student-app 的 Supabase Auth（學生帳密登入），`supabase/schema.sql` 已有資料表草稿
2. **資料上雲**：`self_sessions`、`self_answers`、`kp_mastery`、`review_items` 四張表，配合 RLS
3. **題庫快取**：AI 產生且學生答過的題目存進 `question_bank`，依答對率校正難度；相同知識點優先重用，降低 AI 成本
4. **串接 student-app**：
   - 拍照記錄的錯題（`question_attempts`）可直接成為複習題
   - student-app 的弱點分析可一鍵開自習
   - 老師端看得到學生的自習時數、掌握度變化
5. **遠端指派自習**：館方或 student-app 老師端遠端選範圍＋門檻，學生做到全部過關為止
6. **更多題型**：多選、填充（數值比對）、題組（閱讀）。附圖題已可用（AI 出題可在題幹附 `figure`，由 `GeometryFigure` 畫出）
7. **擴充離線產生器**：理化計算題（密度、歐姆定律、速率）、更多數學單元
8. **激勵機制**：徽章、週報推播、家長週報 Email

## 6. 已知限制（雛形）

- 資料存在瀏覽器 localStorage，換裝置要用「匯出／匯入備份」
- 沒有登入，同一台電腦的多位學生會共用紀錄
- 只有四選一單選題
- 家長日報在學生同一台裝置上，家長還無法在自己的手機收到（需第二階段帳號＋LINE）
- 詳解快取與限流都是單機／單實例版；「題目可能有誤」的標記目前只存在本機
- 沿用 student-app 的 `MathText` 不會渲染 `**粗體**`，AI 詳解的「**思路**」等標題會顯示星號（student-app 同樣現象；建議在 student-app 修正後重新同步）
- 沒設 `GEMINI_API_KEY` 時，只有 27 個數學知識點出真題，其他出示範題
- AI 題目沒有人工審核；正確性靠 prompt 要求自我驗算＋結構驗證，正式上線前建議抽樣檢查

## 7. 無人化智慧 K書中心：場景規劃

> 前提：**館內沒有輔導老師、也沒有值班人員**。學生的學習問題全部由 AI 處理，家長與館方都在遠端。
> 所以系統要自己做到三件事：①學生卡住時有人（AI）接住 ②異常時主動通知家長／館方 ③控制 AI 成本與濫用。

### 7.1 三種角色與一天的流程

```
學生 ── 到館簽到（座位、今日計畫）→ 番茄鐘專注 ／ 自適應練習 ／ 錯題複習
          └─ 卡住 → 🤖 AI 詳解（含幾何圖）→ 看懂了 ✓ ／ 還是不懂 → 追問 AI（最多 3 次）
                                                         └─ 仍不懂 → 排入錯題複習＋家長日報提醒
       → 簽退＋今日心得
家長（遠端）── 到館通知 → 離館通知＋學習日報（LINE）→ 週報 → 留言鼓勵孩子；「AI 講了還不懂」的題目由家長／家教協助
館方（遠端）── 營運儀表板、異常告警、AI 用量與成本、被標記「可能有誤」的題目審核
```

### 7.3 AI 取代現場老師的設計重點

- **同一套解題模組**：提示詞、模型（`gemini-3.7-flash`，thinkingBudget 4096）、答案擷取、科目限制（只用國中已教過的方法）都與 student-app 相同；幾何題附 `figure` 由 `GeometryFigure` 畫出（含輔助線）。
- **不是只給答案**：先顯示系統詳解 → 學生主動要才呼叫 AI；追問時 AI 只針對卡住的那一步、用更小的步驟或例子說明，並以「確認理解的小問題」結尾。
- **講不通要有出口**：追問 3 次仍不懂 → 排入錯題複習（隔天再試）＋家長日報提醒「需要家長或家教協助」。
- **題目品質自我檢查**：AI 詳解答案 ≠ 題目標準答案 → 提醒學生自行驗算並標記給館方。
- **成本與濫用**：詳解快取（同題不重複呼叫）、每來源限流；正式版改以帳號計數並設每日上限、題庫與詳解存雲端共用。

### 7.4 家長通知設計

- **通道**：LINE 官方帳號（Messaging API）為主、Email 為備援。家長以「綁定碼」加入官方帳號並綁定孩子。
- **時機**：到館（即時）、離館（即時＋日報）、週日晚上（週報）、異常（即時）。
- **原則**：先報好消息再報需要關心的地方；不排名、不和其他學生比較；孩子看得到家長會收到什麼。
- 日報文字由 `lib/daily-report.ts` 的 `dailyReportText()` 產生，雛形已可直接複製到 LINE。

### 7.5 隱私與安全

- 未成年人個資：家長綁定須經館方核可；家長只看得到自己的孩子
- 分心偵測只記「離開畫面的次數」，不截圖、不讀其他 App
- 送給 AI 的只有題目與學生的追問文字，不含姓名等個資
- 無人館的裝置：登入逾時自動登出、簽退時清除本機暫存（第二階段帳號上雲後）

### 7.6 第二階段資料表（補充 `supabase/schema.sql`）

`study_days`、`focus_blocks`、`ai_asks`（詳解快取、追問、看懂與否、答案不符標記）、`parents`、`parent_student_links`、`parent_notes`、`notifications`。

### 7.7 建議開發順序

1. 帳號（學生／家長／館方）＋資料上雲 → 家長才能在自己的手機看；AI 詳解快取改為雲端共用
2. LINE 官方帳號綁定＋到館／離館／日報推播
3. 館方遠端看板＋異常告警＋AI 用量上限
4. 題目品質審核後台、自助簽到硬體串接
5. 激勵機制、營運儀表板

## 8. 競品比對後的調整（AIMii，見 `docs/COMPETITOR-AIMii.md`）

無人館沒有真人 Coach，AIMii 的「Coach 每週檢視＋調整」改由系統自動完成。依價值排序建議補上：
1. 每日任務自動派發（到期錯題、昨日弱點、AI 仍不懂的題目 → 3–5 個 15–30 分鐘任務）

3. 家長週報：週增減 %、各科掌握 %、進步曲線
4. 入館體檢（跨單元 15 分鐘定位弱點 → 建議路線）

6. 教科書版本／冊次／進度對應
