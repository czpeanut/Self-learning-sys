# 自習練功房：系統規劃

> 國中生自主學習系統。學生自己選練習範圍，系統出一波題目，**依錯題狀況產生下一波**，結束後產出**學習狀況評估報告**。
> 知識點目錄沿用 [student-app](https://github.com/czpeanut/student-app) 的 `lib/taxonomy.ts`（9 科：科目 → 大單元 → 知識點）。

---

## 1. 核心流程

```
選範圍（科目 / 大單元 / 知識點）＋ 設定（每波題數、波數、難度、計時、過關門檻、目標）
   │
   ▼
第 1 波：程度檢測 ── 每個知識點平均分配題目，難度依歷史掌握度決定
   │
   ▼
逐題作答 ── 選答案 → 依「把握度」送出（有把握／不太確定／用猜的）→ 立即看對錯與詳解
   │         可看提示（會降低加分）、可跳過
   ▼
本波結果 ── 各知識點答對數＋掌握度、錯題錯因標記（自動判斷，可更正）
   │         顯示「下一波計畫」及理由（例：上一波錯 2 題，加強並出變化題）
   ▼
引擎規劃下一波 ── 已過關的知識點移出；錯得多、掌握度低、觀念錯誤的加重；
   │               錯題改出「變化題」（同觀念換數字／情境）；難度依表現升降
   ▼
（重複，直到全部過關／達到波數上限／學生自行結束）
   │
   ▼
學習報告 ── 正確率、各波趨勢、知識點前後掌握度、錯誤類型、自我認知、評語與下一步建議
           錯題自動進錯題本，依 1/2/4/7/15 天間隔排入複習
```

## 3. 自適應引擎設計（`lib/engine.ts`）

### 3.1 掌握度（每個知識點 0–100）
- 題目難度對應門檻分：基礎 35／標準 60／進階 85
- 預期答對率 `p = 1 / (1 + e^(-(掌握度 - 門檻) / 12))`
- 答對：`+K × (1 - p)`，並乘上折扣：不太確定 ×0.7、用猜的 ×0.3、看過提示 ×0.5
- 答錯：`-K × p`；**有把握卻答錯 ×1.2**（觀念錯誤比不會更需要處理）
- K：前 5 次 24（快速定位程度），之後 16
- 等級：<55 待加強、55–79 進步中、≥80 已掌握

### 3.2 錯誤類型（自動判斷，學生可改）
| 類型 | 判斷條件 | 報告給的建議 |
|---|---|---|
| 猜題 | 自己標「用猜的」或跳過 | 先看提示再作答 |
| 粗心失誤 | 有把握，且作答時間 < 建議時間的 25% | 交卷前檢查符號、單位 |
| 觀念錯誤 | 有把握卻答錯 | 重讀定義與詳解 |
| 不熟練 | 不太確定且答錯 | 多做基礎題 |

### 3.3 下一波規劃
1. **過關判定**：本次至少作答 2 題、最近 2 題連對、掌握度 ≥ 門檻 → 移出範圍
2. **優先度** = `(100 - 掌握度) + 30 × 上波錯題數 + 20 × (尚未練過) + 15 × 觀念錯誤數`
3. **題數分配**：依優先度用 D'Hondt 法分配本波題數；單一知識點上限 `max(3, 題數/知識點數)`；剩下的知識點少時縮小這一波的題數
4. **難度**：依掌握度（<45 基礎、<75 標準、其他進階），上波全錯降一級、全對升一級
5. **變化題**：上一波答錯的題，要求 AI 出同觀念、不同數字／情境的題目
6. **結束**：全部過關 → `all-passed`；達到波數上限 → `max-rounds`；學生按結束 → `user-ended`

`npm test` 會跑模擬學生：3 個知識點的真實能力分別是 90／60／25，驗證強項很快過關、後續出題集中在弱項，且掌握度會往真實能力收斂。

## 4. 架構

```
Next.js 14 App Router + TypeScript + Tailwind（與 student-app 相同技術棧，方便日後整合）

app/
  page.tsx                 首頁
  practice/new             範圍選擇＋設定
  practice/session?id=     作答（每題、每波回顧、下一波）
  report?id=               學習報告
  wrong-book               錯題本
  progress                 學習歷程／設定／備份
  api/generate             出題（產生器 → Gemini → 示範題）
  api/report               AI 老師評語
  api/status               是否有設定 AI
lib/
  taxonomy.ts              知識點目錄（student-app 快照）
  types.ts                 資料型別
  engine.ts                自適應引擎（純函式）
  generators.ts            數學離線出題器
  question-gen.ts          出題服務（server）
  report.ts                報告統計＋規則式評語（純函式）
  storage.ts               本機儲存層（之後替換成 Supabase）
  session-client.ts        前端流程控制
```

**設計原則**
- 引擎、報告都是**純函式**，前後端共用、可單元測試；之後搬到 server 端做防作弊也不用改邏輯
- 儲存層集中在 `lib/storage.ts`，換成 Supabase 時只改這個檔案
- 出題有三層備援：程式產生器 → AI → 示範題，AI 塞車時練習不會中斷
- 報告的 AI 評語只送統計摘要（不送題目全文），省 token

## 5. 第二階段規劃

1. **帳號整合**：共用 student-app 的 Supabase Auth（學生帳密登入），`supabase/schema.sql` 已有資料表草稿
2. **資料上雲**：`self_sessions`、`self_answers`、`kp_mastery`、`review_items` 四張表，配合 RLS
3. **題庫快取**：AI 產生且學生答過的題目存進 `question_bank`，依答對率校正難度；相同知識點優先重用，降低 AI 成本
4. **串接 student-app**：
   - 拍照記錄的錯題（`question_attempts`）可直接成為複習題
   - student-app 的弱點分析可一鍵開自習
   - 老師端看得到學生的自習時數、掌握度變化
5. **老師指派自習**：老師選範圍＋門檻，學生做到全部過關為止
6. **更多題型**：多選、填充（數值比對）、題組（閱讀）、附圖題（沿用 student-app 的 `GeometryFigure`）
7. **擴充離線產生器**：理化計算題（密度、歐姆定律、速率）、更多數學單元
8. **激勵機制**：徽章、週報推播、家長週報 Email

## 6. 已知限制（雛形）

- 資料存在瀏覽器 localStorage，換裝置要用「匯出／匯入備份」
- 沒有登入，同一台電腦的多位學生會共用紀錄
- 只有四選一單選題
- 沒設 `GEMINI_API_KEY` 時，只有 27 個數學知識點出真題，其他出示範題
- AI 題目沒有人工審核；正確性靠 prompt 要求自我驗算＋結構驗證，正式上線前建議抽樣檢查
